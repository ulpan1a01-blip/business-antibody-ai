# BUSINESS ANTIBODY AI

Система раннего обнаружения финансовых рисков для малого бизнеса: загружаете данные, она сама находит угрозы (например, кассовый разрыв), объясняет их расчётом, прогнозирует последствия и проверяет решения на цифровом двойнике. Хакатон TREK AI.

Все демо-данные вымышленные. Прогнозы — расчёты при заданных допущениях, не гарантии.

## Статус

## Запуск локально
Нужен Node.js 22.13+.

    cd backend  && npm install && npm start       # http://localhost:3001
    cd frontend && npm install && npm run dev     # http://localhost:5173

Тесты: `cd backend && npm test`. Демо без регистрации: «Посмотреть демо».

Claude API (необязательно): создайте `backend/.env` по образцу `.env.example` и запустите `node --env-file=.env src/server.js`. Без ключа AI-доктор работает в режиме правил.

## Архитектура

    backend/src/engine/   расчёты: finance (метрики, Health Score, прогноз), antibody (детекторы), simulation, memory
    backend/src/          db, auth, importer, repo (данные), decisions, doctor, rateLimit, app (Express), server
    frontend/src/         App, api, components/ (Landing, Auth, Workspace, Diagnosis, Simulation, Import, Memory, Doctor, History)
    docs/                 DB_SCHEMA.md, DEFENSE.md

Принцип: расчёты (`engine/`) — чистые функции без базы и ИИ, поэтому их можно тестировать и объяснять. Express только принимает запросы.

## Публикация на Render
1. Загрузите проект на GitHub (файл `.env` и `*.sqlite` не коммитятся).
2. На render.com: New → Blueprint → выберите репозиторий (используется `render.yaml`) либо создайте Web Service вручную: Build `npm --prefix frontend install --include=dev && npm --prefix frontend run build && npm --prefix backend install`, Start `node backend/src/server.js`.
3. Переменные: `NODE_VERSION=22.13.0`, `DB_PATH=/tmp/data.sqlite`, при желании `ANTHROPIC_API_KEY` (вводится в панели Render).
4. После деплоя откройте адрес сервиса. Один сервис отдаёт и сайт, и API.

Ограничение: на бесплатном плане файловая система временная, база может обнуляться при перезапуске. Для постоянного хранения нужен диск или PostgreSQL.

## Безопасность
Хеши паролей scrypt, токены хранятся хешем, проверка входных данных, ограничение неудачных входов, изоляция данных компаний, заголовки безопасности. Не сделано: CSP, подтверждение email, сброс пароля.
